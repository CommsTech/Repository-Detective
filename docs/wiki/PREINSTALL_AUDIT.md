# Pre-install audit mode (Phase 9)

Repository Detective — **Inspect. Analyze. Improve.**

Pre-install audit lets an operator paste a **public HTTPS** repository URL and receive a **private risk report** plus **copy/paste disclosure drafts** before installing or deploying third-party code. It does **not** connect the repo to your Gitea forge, file issues, send email, or submit reports automatically.

## Flow

```text
paste repo URL → validate URL → shallow git clone → deterministic scanners + static checks + health checks
→ risk score → recommendation → markdown reports → human review → manual action
```

Connected/owned repos continue to use the normal scan → issue → remediation lifecycle. Pre-install audits use separate tables (`audit_requests`, `audit_findings`, `disclosure_reports`).

The `preinstall_cautious` scan profile (see [SCAN_PROFILES.md](SCAN_PROFILES.md)) mirrors this mode for connected repos, but the pre-install audit runner keeps its own cautious runtime (no issue creation, no AI, no dependency install).

## Security boundaries

- Third-party code is treated as **hostile**.
- No operator secrets in clone environment (`minimalGitEnv` — PATH/HOME only).
- No `npm install`, builds, tests, or repo-supplied scripts executed.
- Scanner binaries only (gitleaks, semgrep, trivy, grype, linters when enabled).
- Resource limits: repo size, file count, timeout, max findings.
- Workspace always removed after audit.
- Path traversal and symlink skip reuse `scanners.ValidateWorkspacePath` / walk rules.
- SSRF: HTTPS only, DNS resolution checked against private/loopback IPs (configurable).

## Supported URLs

- `https://github.com/owner/repo`
- `https://gitlab.com/owner/repo`
- `https://gitea.example.com/owner/repo`
- `https://forgejo.example.com/owner/repo`

Rejected by default: `file://`, local paths, SSH URLs, embedded credentials, localhost/private IPs (unless `preinstall_allow_private_networks: true`).

## Configuration

| Key | Env | Default |
|-----|-----|---------|
| `preinstall_audit_enabled` | `REPOSITORY_DETECTIVE_PREINSTALL_AUDIT_ENABLED` | `true` (report-only; enable on-ramp audits) |
| `preinstall_allow_private_networks` | `REPOSITORY_DETECTIVE_PREINSTALL_ALLOW_PRIVATE_NETWORKS` | `false` |
| `preinstall_max_repo_size_mb` | `REPOSITORY_DETECTIVE_PREINSTALL_MAX_REPO_SIZE_MB` | `500` |
| `preinstall_max_files` | `REPOSITORY_DETECTIVE_PREINSTALL_MAX_FILES` | `5000` |
| `preinstall_timeout_seconds` | `REPOSITORY_DETECTIVE_PREINSTALL_TIMEOUT_SECONDS` | `600` |
| `preinstall_max_findings` | `REPOSITORY_DETECTIVE_PREINSTALL_MAX_FINDINGS` | `200` |
| `preinstall_allow_git_clone` | `REPOSITORY_DETECTIVE_PREINSTALL_ALLOW_GIT_CLONE` | `true` |

Requires `database_enabled: true` and `git` on `PATH` when clone is enabled.

## Audit depth

| Depth | Behavior |
|-------|----------|
| `quick` | gitleaks + trivy + static pre-install checks; hadolint runs if enabled and Dockerfile present; checkov skipped |
| `standard` | All enabled deterministic scanners (Go + IaC when applicable) + static checks + health checks |
| `deep` | Same as standard; includes `ai_generated_risk` only when `enable_ai_risk_checks: true` globally |

LLM auditors are **not** run for pre-install audits.

Health findings appear in the install risk summary under **Quality and maintainability notes**. Low-severity health findings use reduced risk score weight so they do not dominate security results. See [HEALTH_CHECKS.md](HEALTH_CHECKS.md).

## Risk scoring (0–100)

Transparent formula stored in `summary_json.risk_explanation`:

- critical +35, high +20, medium +10, low +3
- health/quality findings (tech debt, reliability, maintainability, test gaps, performance): low +1, medium capped at +10
- secret findings: minimum **caution** recommendation
- govulncheck/gosec/hadolint/checkov **high** findings: boosted weight (+25 minimum) for install recommendation
- staticcheck low findings: reduced weight (+1) so they do not dominate
- scanner failure (`binary_missing`, `failed`, etc.): +5 each

Recommendations:

| Score | Recommendation |
|-------|----------------|
| 0–19 | `safe` |
| 20–49 | `caution` |
| 50+ | `do_not_install` |
| audit failed early | `unknown` |

## Report types

| Type | When |
|------|------|
| `install_risk_summary` | Always |
| `security_disclosure` | High/critical security finding, confidence ≥ 0.90 |
| `general_bug` | Other high-confidence non-secret issues |
| `supply_chain_risk` | Install/dependency static findings |

All reports include: *"This report is generated by Repository Detective and should be reviewed by a human before submission."*

- No raw secrets in report bodies.
- No public issue draft for secret findings.
- No email or auto-submit.

- `GET /ui/preinstall` — start audit, recent audits
- `GET /ui/preinstall/audits/:audit_id` — results, findings, copyable reports

## Notifications

When global notifications are enabled, pre-install audits may emit:

- `preinstall_do_not_install` — recommendation is do not install (default enabled)
- `preinstall_caution` — caution recommendation (opt-in via event filter)
- `disclosure_report_generated` — disclosure draft created (opt-in)

Messages include safe repo host/name only — no raw evidence. See [NOTIFICATIONS.md](NOTIFICATIONS.md).

## Limitations (Phase 9)

- Public HTTPS URLs only; shallow clone; no forge API integration.
- No dependency install or build/test execution.
- Scanner binaries may be missing (recorded, audit continues).
- DNS/network required for URL validation and clone.
- Does not add repo to `repositories` table.

## Rollback

1. Set `preinstall_audit_enabled: false` (or `REPOSITORY_DETECTIVE_PREINSTALL_AUDIT_ENABLED=false`).
2. Restart the service.
3. Schema v2 tables are harmless if unused; downgrade requires manual DB backup/restore to v1 if needed.
