# Repository health checks (Phase 10)

Repository Detective — **Inspect. Analyze. Improve.**

Deterministic health checks expand analysis beyond security into maintainability, reliability, tech debt, test gaps, performance footguns, and cautious AI-code-risk signals.

## Design principles

- **Deterministic-first** — no LLM required; health findings skip LLM debate/PoC stages.
- **Evidence-backed** — each finding cites file/line or package-level context.
- **No auto-fixes** — health findings are report-only; optional safe remediation PRs are a separate, operator-controlled feature (see [REMEDIATION_PRS.md](REMEDIATION_PRS.md)).
- **Conservative AI-risk wording** — never claims code was “AI-written.”

## When checks run

| Context | Trigger |
|---------|---------|
| Connected repo scan | `analysis_depth >= 2` and `enable_health_checks: true` |
| Pre-install audit `standard` / `deep` | Health checks enabled (not `quick`) |
| Pre-install AI-risk | Only when `enable_ai_risk_checks: true` and audit depth is `deep` |

Health checks do not install dependencies, execute repo code, or run tests.

## Categories

| Category | Source | Examples |
|----------|--------|----------|
| `tech_debt` | `tech_debt` | TODO/FIXME/HACK, workaround comments |
| `reliability` | `reliability` | Ignored errors, `panic` in libraries, `http.Get` without timeout |
| `maintainability` | `maintainability` | Large files/functions, deep nesting |
| `code_quality` | `maintainability` | Too many function parameters |
| `test_gap` | `test_gap` | Go package without `_test.go`, JS without tests |
| `performance` | `performance` | Regex compile in loop, long `time.Sleep` |
| `ai_generated_risk` | `ai_generated_risk` | Repeated generic comments + generic TODOs (optional, off by default) |

## Configuration

```yaml
enable_health_checks: true
enable_tech_debt_checks: true
enable_reliability_checks: true
enable_maintainability_checks: true
enable_test_gap_checks: true
enable_performance_checks: true
enable_ai_risk_checks: false   # cautious default

health_max_findings: 100
health_large_file_lines: 1000
health_large_function_lines: 150
health_max_nesting_depth: 5
health_max_function_params: 7
```

Env: `REPOSITORY_DETECTIVE_ENABLE_HEALTH_*`, `REPOSITORY_DETECTIVE_HEALTH_*`.

Per-repo health toggles are supported via `repo_settings` (Phase 10B). Nullable fields inherit global config. Pre-install audits use global pre-install policy only — not per-repo health overrides.

## Pipeline integration

1. Health checks produce `models.CandidateFinding` with `AuditorType` = source (`tech_debt`, etc.).
2. Sources register as deterministic via `scanners.RegisterDeterministicSource`.
3. Validate/Prove stages skip LLM for all deterministic findings.
4. Findings persist through existing fingerprint/issue/store paths.

## Pre-install behavior

- Health findings appear in audit results and install risk summary under **Quality and maintainability notes**.
- Low-severity health findings contribute reduced risk score points (capped) so they do not dominate security results.

## AI-risk wording rules

Allowed:

- “Possible low-context or AI-generated code risk — review recommended”

Not allowed in issue titles/descriptions:

- “AI-written”, “generated by AI”, “slop”, “vibe coded”

Enable only when you accept higher false-positive rate: `enable_ai_risk_checks: true`.

## False positives

- TODO comments in issue trackers may trigger tech-debt findings — tune with `enable_tech_debt_checks: false`.
- `_ = conn.Close()`-style ignores are suppressed; other ignored errors may need manual review.
- Large-file thresholds may flag generated code — increase `health_large_file_lines`.

## Beta default reporting

Under the `beta_standard` profile, low-severity health findings (`HEALTH-TECH-MARKER`, `HEALTH-LARGE-FILE`) and medium reliability markers remain on the **dashboard only** — they do not create Gitea issues unless the repo uses `strict_security` or explicit `issue_only` with lower severity gates. See [POLICY.md](POLICY.md#issue-policies).

## Per-repo examples (Phase 10B)

Strict security repo with health but no AI-risk:

```yaml
# PUT /api/v1/repos/:id/settings
enable_health_checks: true
enable_ai_risk_checks: false
analysis_depth: 2
```

Legacy monolith with relaxed thresholds:

```yaml
health_large_file_lines: 3000
health_large_function_lines: 250
enable_reliability_checks: true
enable_test_gap_checks: true
```

Pre-install audits always use global config — per-repo health overrides apply only to connected repository scans.

## Rollback

Set `enable_health_checks: false` and restart. No schema migration required.
