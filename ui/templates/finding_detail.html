Dependency fix-first checklist · what to verify before a PR
  1. Validate the finding. Confirm the scanner's package, installed version, and advisory against the exact source revision.
  2. Check the upgrade path. Determine direct versus transitive dependency ownership, confirm a supported patched version, and inspect release notes for breaking APIs.
  3. Prioritize by exposure. Check known exploitation and actual runtime reachability; an EPSS score is not proof of reachability. Treat unknown exposure as unknown.
  4. Test away from production. Update manifests and lockfiles together in an isolated workspace with restricted credentials and network access. Build and run regression tests.
  5. Prove the fix. Rescan the exact resulting commit with required scanners; only verify closure when coverage is complete and the vulnerability no longer appears.

AI can recommend changes, but it cannot bypass review or verification. No scanner-reported fixed version? Track a mitigation instead of inventing a safe upgrade.
